Run these for performance metrics. Each uses MCP mode (the path opencode uses), for the internal HPE CA, and saves JSON.

1. Multimodal dataset — andrew-test-dataset (664 docs), no reranker:
python3 benchmark.py --mode mcp \
  --url http://rag-mcp-server-mcp.mm-rag-mcp.svc.cluster.local:9090/mcp \
  --api-url http://rag-mcp-server-api.mm-rag-mcp.svc.cluster.local \
  --dataset andrew-test-dataset \
  --N 100 --duration 30 --ramp-up 5 --top-k 10 \
  --output mm_no_reranker.json

2. Multimodal dataset — with reranker (measures cross-encoder latency cost):
python3 benchmark.py --mode mcp \
  --url http://rag-mcp-server-mcp.mm-rag-mcp.svc.cluster.local:9090/mcp \
  --api-url http://rag-mcp-server-api.mm-rag-mcp.svc.cluster.local \
  --dataset andrew-test-dataset \
  --N 100 --duration 30 --ramp-up 5 --top-k 10 --use-reranker --reranker-top-k 5 \
  --output mm_reranker.json

Notes:
- I confirmed the dataset names via the MCP server: the text-only one is stack-project (you wrote stacks-project).
- --api-url is required because the script otherwise derives host:8000, which this external virtual service doesn't expose.
- Tune --N (concurrency) and --duration up for steadier percentiles — e.g. --N 50 --duration 60 for a heavier load run.
- Pre-existing caveat: in MCP mode the script records avg_results/query as 1 (it can't parse result counts from MCP text content), so rely on req/s and latency percentiles for comparison.
