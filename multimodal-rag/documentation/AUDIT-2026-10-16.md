## P0 (fix before anything else)

### P0-1 — Unauthenticated impersonation, default-on, with durable-key escalation
`api_server.py:1114-1129` accepts `X-Auth-Request-Preferred-Username` / `X-Auth-Request-User` as a `proxy-identity` credential whenever `RAG_TRUST_PROXY_IDENTITY` is set; `clients_registry.py:467-476` maps that NAME straight to `_client_identity_for(name)` — the registry identity with its grants, no secret required. All three charts ship `security.trustProxyIdentity: true` (helm/values.yaml:198, medium:252, large:255) and `RAG_ACCESS_SELF_MINT: "true"` (configmap.yaml:89/90/93). Reproduced: with no credential at all and only the header, read (200), **write** (200), and listing (`owned_by_me: true`); without it, 401. Escalation chain verified by the lead statically: spoofed name → `_require_self_mint` accepts `proxy-identity` as SSO proof (api_server.py:2398-2402) → `POST /api/access/mint-key` (2468) issues a durable key carrying the victim's grants. Amplifier: the AuthorizationPolicy selects the istio-ingressgateway pod, NOT the app pods — a direct ClusterIP call never traverses it; NetworkPolicy defaults off; the scale charts ship none.
The code's own precondition ("the app cannot be reached with attacker-set values", :1117-1118) is documented but not enforced by the chart.
**Fix:** invert the chart default to false (sites truly behind oauth2-proxy set it explicitly); require a positive proxy-injected assertion (e.g. signed header) rather than absence of a competing credential; reposition the AuthorizationPolicy to select the app pods too.

### P0-2 — Dataset media serving bypasses the dataset ACL entirely
`api_serve_file` is in `_PUBLIC_ENDPOINT_NAMES` (api_server.py:893), so `_is_public_path` (904-911) returns `call_next` at :1269 BEFORE the D20 fail-closed branch and before `_rag_acl_path_denial` (1003) ever run. The handler's only gate is `_require_dataset_password` (4864-4930), which returns immediately for a passwordless dataset (:734-735). Reproduced by two independent zones: an ACL-denied key 403s on metadata/search/documents but gets **200 + bytes** on `/files/…`; an unauthenticated caller likewise; the bare-filename glob fallback (4908-4923) also 200s. The middleware comment "media/staged serving authorize themselves" is true only for password/token datasets.
**Fix:** remove `api_serve_file` from the public list and enforce the ACL inside the handler (password/token remains sufficient *plus* ACL-allowed, or identity-checked); keep healthz/pages truly public.

## Test gaps (why the big ones survived)

Baseline suites were GREEN on this tree while the wave found 2 P0 + 11 P1 — the gap is structural, not sloppiness:
1. **No middleware-order tests.** P0-2 lives in the exemption list ordering; nothing asserts ACL runs before public-path return for media routes.
2. **No cross-surface contract tests.** REST and MCP twins are tested separately, so opposite orderings (P1-9, P2-4) both pass their own suites. A parity table test (same request via both surfaces → same decision) would have caught three of these.
3. **No default-values tests.** Chart defaults (trustProxyIdentity, SELF_MINT, MEDIA_BASE_URL-vs-VS-disabled, NetworkPolicy presence per chart) are never rendered-and-asserted; a `helm template` golden test per chart would have caught four.
4. **No negative-validation tests on body endpoints** — GET twins get ge/le coverage; POST twins get none (P1-10).
5. **Success-path-only media tests** — truncation/resize tested for "did it transcode", never "did it return the NEW path / check returncode" (P1-4, P2-8).
